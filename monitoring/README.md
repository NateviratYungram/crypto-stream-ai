# 📊 Monitoring — Data Observability Stack (Phase 5)

## Overview

This directory contains the full **Observability Stack** for CryptoStream AI, built on **Prometheus + Grafana**. It monitors pipeline health, data quality, and regulatory SLA compliance in real-time.

**Banking Relevance:** Virtual Banks must demonstrate to the BOT that their data systems are continuously monitored, with automated alerting for SLA breaches and data quality failures.

---

## 📁 Directory Structure

```
monitoring/
├── prometheus.yml                          # Prometheus scrape config (all services)
├── alertmanager.yml                        # Alert routing (critical → PagerDuty, BOT → compliance channel)
├── docker-compose.monitoring.yml           # Launch monitoring stack
├── rules/
│   └── alert_rules.yml                     # Alerting rules (SLA, DQ, Flink, PostgreSQL)
└── grafana/
    ├── dashboards/
    │   ├── cryptostream_overview.json      # Main pipeline dashboard (9 panels)
    │   └── data_quality.json              # DQ pass rate, DLQ trends, failure breakdown
    └── provisioning/
        ├── datasources/prometheus.yaml     # Auto-configure Prometheus
        └── dashboards/dashboard.yaml      # Auto-load all JSON dashboards
```

---

## 🚀 Quick Start

```bash
# 1. Start main pipeline first
docker compose up -d

# 2. Start monitoring stack (attaches to same network)
docker compose -f docker-compose.yml -f monitoring/docker-compose.monitoring.yml up -d

# 3. Access UIs
# Grafana:      http://localhost:3000  (admin / cryptostream_admin)
# Prometheus:   http://localhost:9090
# Alertmanager: http://localhost:9093
```

## 🚨 Alert Rules (`rules/alert_rules.yml`)

| Alert | Condition | Severity | Compliance |
|---|---|---|---|
| `KafkaConsumerLagCritical` | Lag > 10,000 for 2m | Critical | BOT SLA |
| `KafkaConsumerLagWarning` | Lag > 1,000 for 5m | Warning | — |
| `DataQualityFailureRateHigh` | DQ fail > 5% for 5m | Warning | AMLO Audit |
| `DataQualityFailureRateCritical` | DQ fail > 20% for 2m | Critical | AMLO Audit |
| `FlinkJobNotRunning` | 0 running jobs for 1m | Critical | — |
| `FlinkCheckpointFailed` | > 3 failures in 5m | Warning | — |

| `PostgresConnectionsNearLimit` | Connections > 80 for 5m | Warning | — |

## RAG Ops Monitoring

The backend now exposes RAG metrics at `http://chat-server:8888/metrics`, and
Prometheus scrapes them through the `chat_server` job. Grafana automatically
loads `monitoring/grafana/dashboards/rag_ops.json`.

| Metric | What it means |
|---|---|
| `cryptostream_rag_retrievals_total` | Total RAG retrieval volume by tenant |
| `cryptostream_rag_latency_p95_ms` | P95 retrieval latency for user-facing answers |
| `cryptostream_rag_estimated_cost_usd_total` | Estimated cumulative embedding cost |
| `cryptostream_rag_experiment_retrievals_total` | Baseline vs hybrid reranker A/B traffic |
| `cryptostream_rag_feedback_negative_ratio` | Human annotation quality signal |
| `cryptostream_rag_annotation_queue_items` | Retrievals waiting for review |

Additional alerts:

| Alert | Condition | Severity |
|---|---|---|
| `RagLatencyP95High` | RAG p95 latency > 2s for 5m | Warning |
| `RagHourlyEstimatedCostHigh` | Estimated RAG cost increase > $0.05/hour | Warning |
| `RagNegativeFeedbackRatioHigh` | Negative feedback ratio > 30% for 10m | Warning |
| `RagRetrievalSpike` | > 300 retrievals in 5m | Warning |
